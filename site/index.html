Let AI assistants book salon appointments. The customer approves every one.

Cresavo Gateway is the agent-facing front door to Cresavo salons. Your assistant finds free times and proposes a booking. The customer says yes on their own phone. Only then does the salon book it, exactly as approved.

Demo phase: the salon behind this gateway, “Salong Eko”, is fictional. Use fictional contact details only.

Principles

Consent built in

Every booking runs on a mandate the customer approved. Change the price, staff or time and it no longer counts.

No database

Only in-memory rate-limit counters keyed by IP. No logs of bodies or credentials. The salon owns the calendar, the data and every decision.

Standard protocols

MCP over Streamable HTTP for agents, REST with OpenAPI 3.1 for everything else. Same operations on both.

Safe to retry

Timed out? Retry with the same idempotency key and get the original booking back, never a duplicate.

Connect

Two transports, one contract. Pick whichever your agent speaks.

MCP Streamable HTTP

One JSON-RPC message per request.

{{ORIGIN}}/api/v1/mcp

Add it to any MCP client that supports remote servers and custom headers:

{
  "mcpServers": {
    "cresavo": {
      "type": "http",
      "url": "{{ORIGIN}}/api/v1/mcp",
      "headers": { "Authorization": "Bearer ${CRESAVO_AGENT_KEY}" }
    }
  }
}

REST OpenAPI 3.1

The same operations as plain HTTP.

{{ORIGIN}}/api/v1
curl "{{ORIGIN}}/api/v1/services?business=demo" \
  -H "Authorization: Bearer $CRESAVO_AGENT_KEY"

Download the OpenAPI contract. Discovery for agents: /.well-known/usp and /llms.txt.

Credentials. Agent credentials are issued by the salon provider, never by the gateway. Send them in the Authorization header only. Never put them in URLs, prompts or chat. To request demo access, open an issue.

What the gateway never does

These are tested, not promises. Read the full security model.

  • Invent a booking result. No salon answer means no booking.
  • Reuse an access check across requests.
  • Forward browser sessions, cookies or client IP headers.
  • Store customer data, or log credentials or request bodies. It has no database; only in-memory rate-limit counters keyed by IP.
  • Take payments, export data or bulk delete.
